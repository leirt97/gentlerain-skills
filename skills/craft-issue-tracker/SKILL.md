# Craft 问题跟踪

## 执行

1. 从当前项目规则或用户上下文确定客户端、配置入口、目标文档、集合、模板及迁移范围；缺少必要绑定时只追问该项。创建、迁移或更新状态遵循 [流程与权限](references/workflow.md)，写日志或整理详情遵循 [日志格式](references/log-format.md)。
2. 读当前记录及 schema，按字段名称解析 key（包括主标题），核验目标与重复项；按 [接口注意事项](references/api-notes.md) 调用。
3. 执行 API 支持的修改。需界面操作的字段、模板或视图，一次交给用户一个明确步骤，完成后回读。
4. 每次写入逐项回读，核验状态、正文、块顺序、时间、数量并保护用户同期编辑。结构改造先核验新内容完整，再清理旧内容；失败或结果不明时按现有块 ID 检查已完成部分后继续。

## 交付

报告实际新增/更新数、当前状态、回读结果及待用户完成的界面步骤；区分 API 回读与看板渲染验收。
