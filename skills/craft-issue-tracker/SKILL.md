# Craft 问题跟踪

## 执行

1. 从当前项目规则或用户上下文确定客户端、配置入口、目标文档、集合、模板及迁移范围；缺少必要绑定时只追问该项。创建、迁移或更新状态遵循 [流程与权限](references/workflow.md)，写日志或整理详情遵循 [日志格式](references/log-format.md)。
2. 读当前记录、schema 及中央编号登记合集，按字段名称解析 key（包括主标题），核验目标与重复项；为每条问题建立来源与编号决策，按 [编号契约](references/workflow.md#编号契约) 解析。写入前，编号决策须无来源冲突、时间缺口和重复值；按 [接口注意事项](references/api-notes.md) 调用。
3. 基础合集和字段按 [API 边界](references/api-notes.md#合集创建边界) 执行；用户问题先在中央登记合集预留编号，再写入目标问题合集，目标写入回读确认后将登记状态更新为已写入。API 未覆盖的模板或视图配置才进入明确的界面步骤，完成后回读。
4. 每次写入逐项回读，核验编号登记、编号、状态、正文、块顺序、时间、数量并保护用户同期编辑。来源记录含 `sourceMedia` 时，同时核验媒体块的字段标签、原始顺序、数量、上传字节数和 Craft block ID；文字投影为空时，以媒体清单和块回读作为内容证据。结构改造先核验新内容完整，再清理旧内容；失败或结果不明时按现有块 ID 检查已完成部分后继续，已预留编号不回收。

## 交付

报告实际新增/更新数、当前状态、编号决策、登记记录与回读结果及待用户完成的界面步骤；区分 API 回读与看板渲染验收。完成标准是每条目标问题的编号和来源证据（含 `sourceMedia` 时的媒体清单）都可回溯，并在中央登记合集有唯一记录，或明确记录为待补证据。
