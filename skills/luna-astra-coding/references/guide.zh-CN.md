# 当前模型优先，Astra 按需委派

这是英文执行技能的中文对照，供你阅读；英文 `SKILL.md` 和 `references/dispatch.md` 是维护源。修订时同步本说明，执行时无需重复加载两种语言。

默认由 **当前会话所用模型负责沟通、实现、审查和验证**，保留当前 effort 设置，自主判断是否值得委派 **Astra / low**；用户可以明确指定子智能体的其他 effort。无需选择 Luna，也不因无法获取主模型名称而要求确认或暂停。技能不切换模型、不修改默认模型配置。

技能标识仍为 `luna-astra-coding`，保留原调用方式和目录身份，名称不再代表固定使用 Luna。

## 谁来写代码

当前会话模型默认独立完成任务并验证。在满足质量与验收要求的前提下，权衡总成本，包括委派开销与返工成本，自行判断 Astra 子智能体的预期收益是否值得委派。

当子智能体有望改善正确性或减少返工，且收益值得委派开销时，委派处理。委派时用一句话说明技术难点；不要仅因涉及代码或一次验证失败而委派。缺少证据或用户决策时，先解决对应缺口。

如果当前会话本身就是 Astra，委派不代表模型能力升级；仍需判断全新 worker 的收益是否值得其开销。Astra 担任主管时正常实现、审查和验证，下文“写完即停”等限制只适用于被委派的 Astra 子智能体。

“改哪里、为什么这样改、怎样验证”仅作为可选思考提示，不是固定步骤、评分表或委派前置条件。无需每次报告路由判断。具体任务、验证代码及返修均使用同一自主判断原则。

## 升级时如何委派

使用 `collaboration.spawn_agent`，明确设置：

- `model="gpt-6-astra"`
- `reasoning_effort="low"`，用户指定时遵从用户
- `fork_turns="none"`

**不分叉长任务，不继承历史，不复用旧 worker。** 禁止 `all`、正整数历史继承和 `fork_thread`；每次升级或困难返修都创建全新子智能体。全新上下文仍包含宿主、系统和项目规则，并不等于零开销。

交接只保留本次实现所需的信息。提供准确路径和符号，按需读文件，不复制完整聊天、完整日志、凭据或无关内容。

```text
角色：Astra 编码子智能体，只负责实现。
工作目录与状态：绝对路径、分支/版本、已有改动。
目标：本次单一交付结果。
升级原因：用一句话说明尚未解决的技术难点。
修改范围：允许修改的模块/文件，以及需保护的用户改动。
读取入口：AGENTS.md、相关符号、必需契约。
验收标准：可观察的预期行为，由当前会话主管验证。
故障证据（如有）：复现、预期/实际、短错误、完整证据路径。
测试代码（如需）：需要编写什么，但不执行。
停止条件：实现后仅返回路径、简短变化、假设/阻塞与 NOT_TESTED。
不自我审查，不跑测试、lint、构建，不操作浏览器或截图，不委派、不提交。
缺少必需输入时返回阻塞，不自行编造业务行为。
```

模型与能力以运行时工具 schema 为准。无法指定 Astra 或创建全新上下文时，报告依赖此能力的工作受阻，不擅自换模型；继续独立且已授权的工作。子智能体共享目录，同一文件范围只允许一个写入者，写完再验证。

不自动创建侧边栏独立任务；只有用户明确要求时才用 `create_thread`，按工具要求选择项目和环境，并等待结果、核实改动目录。worker 结束后若没有关闭工具，闲置且不再使用即可，无需为清理删除文件或归档用户任务。

## 谁来验证和返修

Astra 子智能体只负责本次实现，写完即停。当前会话主管审查实际差异的正确性、可读性、契约与范围，运行测试、lint、构建，处理网页报错、截图及必要的应用或真机验收。

当前会话主管默认负责编写测试和诊断脚本、使用适合的自动修复工具。验证代码和返修仍由主管自主判断是否值得委派，不受上一轮作者影响。Astra 子智能体可以写测试代码，但不执行；每次委派均使用全新 worker。

最终报告包括变化、验证结果及对应文件/版本状态、剩余阻塞。没有测试、登录或设备受阻、检查失败，均与通过结果分开说明。子智能体完成只表示实现完成，必要验收完成才表示任务完成。交付、提交、发布继续遵守已有授权与更高优先级规则；冲突须在依赖工作前说明。

## 如何使用

在当前会话或新任务中直接输入，无需切换模型：

```text
使用 $luna-astra-coding 完成以下需求：……
```

该路由只作用于当前任务，不修改全局配置。减少不必要的委派是设计目标；真实模型遵循率、成本和配额净节省仍需实测，不能由静态校验推出。
